# Mermaid 작성·검증

Mermaid를 생성, 수정, 분리하거나 구조를 검증할 때만 읽는다. 이 파일은 Mermaid 작성·검증 정책 자체가 바뀐 경우에만 갱신한다. Git 기준선과 수정 범위는 SKILL.md를 따른다.

## 작성 규칙
- Flowchart의 책임 영역은 `subgraph`로, Sequence Diagram의 참여자는 `box`로 구분한다.
- 정상 흐름과 예외 흐름이 복잡하면 다이어그램을 분리하고, 분리한 다이어그램 사이의 연결 상태를 본문에 설명한다.
- 실제 클래스, 함수, 상태, API 이름을 사용한다.
- 긴 정책 설명은 노드가 아니라 본문에 쓴다.
- 색상과 장식보다 책임 경계와 실행 순서를 우선한다.
- 하나의 다이어그램에 과도한 노드와 조건을 넣지 않는다.
- 중복 노드 ID를 쓰지 않고, `end`를 노드 ID로 쓰지 않는다.

## 정적 검증
수정한 Mermaid 블록 내부에서 확인한다.
- 코드 fence의 시작과 종료
- `subgraph`와 `end`의 짝
- `box`, `alt`, `loop`, `opt`와 `end`의 짝, `else`의 위치
- 중복 노드 ID
- 문서에 쓴 클래스·메서드의 실제 존재 (심볼 확인 방법은 implementation-invariants.md)
- `TaskState`, `StepState`, `ApprovalType`, `CliOutcome` 값이 `app/models/states.py`와 일치
- Router URI, HTTP 상태 코드, WebSocket 경로가 `app/routers/`와 일치

opener와 `end`의 개수가 같다는 것만으로 성공으로 판단하지 않는다. 블록 구조를 직접 읽어 짝을 확인한다.

## 렌더링
현재 shell에서 `mmdc`가 이미 설치되어 있는지만 확인한다. 설치되어 있을 때만 렌더링으로 검증한다.
설치되어 있지 않으면 자동 설치, `npm install`, `npx` 다운로드, 네트워크 접근을 하지 않고 "정적 구조 검증 완료, 실제 렌더링 미검증"이라고 보고한다. 렌더링을 검증하지 못했는데 성공으로 보고하지 않는다.

## 범위 검증
- 종료 시 기준선과 비교해, 이번 동기화가 허용 범위 밖에 새 변경을 만들지 않았는지 확인한다.
- 기존 코드 diff가 있다는 이유만으로 실패 처리하지 않는다. 기존 변경은 되돌리지 않는다.
