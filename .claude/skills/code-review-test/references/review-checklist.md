# 코드 리뷰 체크리스트

위에서 아래 순서로 검토한다. 정상 경로보다 실패·경합 경계를 우선한다.

1. **요구사항과 구현의 불일치**: 요청·계획·API 계약과 실제 동작이 다른 부분.
2. **잘못된 상태 전이와 terminal 상태 처리**: 허용되지 않는 전이, terminal 이후의 재진입·덮어쓰기.
3. **transaction 경계와 부분 commit**: 여러 쓰기가 한 경계 안에 있는지, 중간 실패 시 일부만 남는지.
4. **claim token, lease, ownership fencing**: stale owner가 검증 이후 상태를 기록할 수 있는지, 토큰 없이 변경되는 경로가 있는지.
5. **cancellation과 cleanup**: 취소 시 자원 정리가 보장되는지, 취소가 정리 코드를 건너뛰는지.
6. **semaphore, lock, connection의 획득·반환 대칭성**: 모든 경로(예외·취소 포함)에서 반환되는지.
7. **restart와 recovery의 멱등성**: 같은 recovery를 반복해도 결과가 같은지, 중복 효과가 없는지.
8. **timeout과 무제한 대기**: 대기 지점에 상한이 있는지.
9. **예외 우선순위와 오류 은폐**: cleanup 예외가 원인 예외를 덮는지, 광범위 except가 실패를 삼키는지.
10. **fail-open과 fail-closed 경계**: 검증·권한·snapshot 실패 시 안전한 쪽으로 닫히는지.
11. **API 입력에서 생략과 명시적 null 구분**: 필드 생략과 null이 다른 의미인지, 같게 처리되고 있지 않은지.
12. **이전 데이터 또는 fingerprint version 호환성**: 기존 row·저장 값·이전 version을 안전하게 읽는지.
13. **순환 import와 계층 역전**: 하위 계층이 상위 계층을 import하는지.
14. **사용자 변경 및 범위 밖 파일 영향**: 변경이 요청 범위를 벗어나거나 기존 사용자 변경을 훼손하는지.

## 발견 사항 형식
- 심각도: Critical, High, Medium, Low
- 근거 파일과 가능한 경우 줄 번호
- 재현 조건
- 실제 영향
- 최소 수정 방향
- 필요한 회귀 테스트

## 작성 규칙
- 단순 스타일 선호는 correctness 문제와 분리해 따로 표기한다.
- 확인하지 못한 내용은 "추정" 또는 "미검증"으로 표시하고 확정 결함처럼 쓰지 않는다.
